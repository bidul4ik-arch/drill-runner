# Кампания DrillDrop — проверка 17 сентября 2026

## Результат

Три отдельных уровня: Старая шахта (420 м), Кристальные пещеры (540 м), Буровой комплекс (660 м). Каждый включает введение, дистанцию, контрольную точку, босса с двумя фазами и окно уязвимости, награду и переход в домик. Следующий уровень открывается, но не запускается автоматически. Бесконечный режим сохранён отдельно.

## Фактические проверки

- Сначала пройден первый уровень: 4 попадания буром, 10 атак робота, две фазы, победа.
- Затем сквозное прохождение через графический Godot 4.2.2 / OpenGL: все 3 уровня — victory, соответственно 4730 / 4977 / 7615 шагов по 1/60 с; 10 / 10 / 21 атака. **0 failures**.
- Автоматический игрок выбирает полосы, прыгает и делает подкат при приближении волны и нажимает бур в нужной полосе. Здоровье боссов не изменяется напрямую; бессмертие в playthrough-тесте не используется. В performance-тесте бессмертие используется только для замера рендера.
- Системные проверки: обе валюты, стоимость скинов, повтор покупки, недостаток средств, сохранение выбранного скина, pending/cancelled/failed/unverified платежи, повтор verified-транзакции, сохранение pending, контрольная точка каждого босса, сброс здоровья при повторе, неправильная полоса бурового удара, пауза и возврат из настроек/фона. **0 failures**.
- Все атаки проверены на наличие свободной полосы либо полной волны, проходимой прыжком/подкатом. Между атаками минимум 1,25 с предупреждения + 1,3 с движения + 0,65 с восстановления. Окно уязвимости минимум 3,8 с. Случайные препятствия и предметы удаляются из активной трассы при начале босса и не генерируются до нового забега.
- Переходы меню → домик, 12 переходов: число узлов **38 → 38**. Сцены освобождаются; загрузка сопровождается затемнением и экраном загрузки.
- Рендер 300 кадров каждого босса, Apple M2, качество 60 FPS: **56,98 / 59,87 / 59,68 FPS**. Это настольный замер; Android/iOS производительность не проверена. Предусмотрен режим 30 FPS без направленных теней.
- Серверное ядро ledger: атомарное начисление, повтор receipt, повтор списания, восстановление после переоткрытия базы, привязка транзакции к аккаунту, очередь acknowledgement. Все проверки пройдены с mock verifier, без подключения магазинов.
- Визуально проверены кадры меню, домика, гардероба, уровней и боссов. Исправлены поворот боссов, пустые счётчики при запуске с контрольной точки и оформление шкалы здоровья.

## Ограничения

- Android APK: экспорт предпринят, но отклонён из-за конфигурации SDK/JDK. Подробности в NOTES_ANDROID.md. iOS-сборка и физические устройства не проверены. Safe area и свайпы реализованы, реальный вырез экрана и вибрация на устройстве не проверены.
- Оплата не подключена. Нет зарегистрированных товаров, нативных billing/StoreKit мостов, серверного verifier, аккаунтного API, ключей магазинов и тестовых аккаунтов. В production покупка недоступна. `--test-store` включает явно маркированную имитацию без реальных денег. Подготовленная часть и официальные источники — Server/INTEGRATION.md.
- Новый арт стилизован и проще концептов. Боссы имеют реальные модели и анимации; механика боя реализована, но визуальное качество не равно высокодетализированным концептам.
- В headless dummy renderer Godot 4.2.2 при освобождении процедурных мешей боссов появляются `Parameter m is null`; в графическом прогоне кампании их нет. Иногда при завершении старый WAV-плеер сообщает ObjectDB/Resources still in use. Это не объявляется устранённым. Проверки стабильности относятся к узлам сцен, не ко всем выделениям драйвера.

Сохранения тестов отделены в `user://campaign_test.json`. Обычная игра — `user://campaign.json`, с миграцией монет/рекорда из прежнего progress.cfg при первом запуске. Настоящий премиальный баланс не хранится локально: реальная экономика отключена, в файле есть только test_premium.

Дополнительно проверено сохранение снимка незавершённого уровня при паузе/сворачивании: 123,5 м и 7 монет восстановились через «Продолжить». После восстановления обычной дистанции даётся чистый начальный участок для безопасного возврата; бой восстанавливается с предбоссовой контрольной точки, с полным здоровьем босса. Тестовый магазин запускается с отдельным `campaign_sandbox.json`, не меняя обычное сохранение.

Финальная проверка готового macOS-приложения: внешний тестовый сценарий загружен поверх экспортированного PCK; игровые сцены, настройки и ассеты использованы из сборки. Все три уровня снова завершены с `CAMPAIGN TEST: 0 failures`. Лог — `packaged-playthrough-results.txt`. После сохранения и повторного чтения JSON дополнительно проверены целочисленные ID пройденных уровней, открытые уровни и выбранный скин. Windows x64 переэкспортирован с теми же исправлениями; запуск Windows на этом Mac не проверялся.
